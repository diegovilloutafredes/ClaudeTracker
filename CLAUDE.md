# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ClaudeTracker — a macOS menu bar app that monitors Claude AI usage limits in real time. It polls the unofficial claude.ai web API and displays utilization percentages and reset countdowns. Open source, MIT licensed.

## Build & Deploy

Use the Makefile. Full clean cycle is required for every change (macOS caches stale binaries otherwise):

```bash
make run   # clean + build + install into /Applications/ + launch
```

Other Makefile targets:

| Target | Purpose |
|---|---|
| `make run` | Clean + build + install into `/Applications/` + launch |
| `make build` | Clean + build Release into `release/build/` |
| `make generate` | Generate `ClaudeTracker.xcodeproj` from `project.yml` (XcodeGen); `build`/`test`/`run` run this first |
| `make zip` | Package `release/dist/` → `release/ClaudeTracker.zip` (with `install.command`) |
| `make dmg` | Create `release/ClaudeTracker.dmg` with Applications symlink via `hdiutil` |
| `make sign` | Codesign with `--options runtime`; silently skips if `SIGN_IDENTITY` not set |
| `make notarize` | Submit to Apple notarization; silently skips if `APPLE_ID` not set |
| `make staple` | Staple the notarization ticket; silently skips if `APPLE_ID` not set |
| `make release` | Full pipeline: build → sign → notarize → staple → dmg → zip |
| `make tag VERSION=x.y.z` | Bump `MARKETING_VERSION` in `project.yml`, commit, tag, push — triggers CI release |
| `make clean` | Remove all build artifacts |

Never `cp -R` over an existing `/Applications/ClaudeTracker.app` — Launch Services caches the old binary. Always delete first, then copy. `make run` and `install.command` both do this automatically.

The app icon is generated by `scripts/generate-appicon.swift` (run `swift scripts/generate-appicon.swift` from the repo root) — it redraws the "bolt + gauge" design with CoreGraphics and overwrites all 10 PNGs in `AppIcon.appiconset/`. The PNGs are committed; the script is regeneration tooling, not a build step. Design spec: `docs/superpowers/specs/2026-06-04-app-icon-refresh-design.md`.

Requires macOS 14+ (Sonoma), Xcode 15+, and [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`). The Xcode project is generated from `project.yml` and is **not** committed — `make generate` (run automatically by `build`/`test`/`run`) produces it. The app itself has no runtime dependencies.

## Releases

Cutting a release:

```bash
make tag VERSION=1.2.0
```

This requires a clean working directory. It bumps `MARKETING_VERSION` in `project.yml` (the XcodeGen source of truth — the `.xcodeproj` is generated and git-ignored), commits the bump, creates an annotated git tag, and pushes both the commit and the tag. The GitHub Actions release workflow (`.github/workflows/release.yml`) triggers on the tag and publishes a GitHub Release with the zip attached.

The build uses `SIGNING_FLAGS="CODE_SIGNING_ALLOWED=NO"` on CI. **Strict concurrency:** `project.yml` sets `SWIFT_STRICT_CONCURRENCY: complete` at the project level — the codebase builds warning-free under it (verified on Xcode 26.5, the CI toolchain). The old per-invocation `SWIFT_STRICT_CONCURRENCY=minimal` workaround flags were removed from the Makefile and workflows once the offending sites (nonisolated Timer/Combine/Dispatch closures) were converted to MainActor task loops. Keep new code `complete`-clean; do not reintroduce the minimal flag.

CI: `.github/workflows/build.yml` runs lint + Release-configuration build + tests on every push/PR (Release on purpose — wholemodule optimization surfaces diagnostics Debug misses, and Release is what ships). `release.yml` also runs lint + tests before building, and `make tag` depends on `lint test` locally. Both workflows share the Xcode path via an `XCODE_PATH` env var (keep them in sync).

The release workflow (`.github/workflows/release.yml`) has conditional signing: a `Check signing capability` step outputs `sign=true/false` based on whether `SIGNING_CERTIFICATE` is set as a repo secret. Subsequent sign/notarize/staple steps gate on this output. Both a DMG and a ZIP are attached to every GitHub Release; the ZIP includes `install.command` as a fallback for unsigned installs.

## Architecture

- **ClaudeTrackerApp.swift** — App entry point using `MenuBarExtra` with `.window` style (no dock icon via `LSUIElement`). The label uses a single `Image(nsImage:)` with a composed NSImage. The `init()` calls `SandboxMigration.runIfNeeded()` *before* allocating `UsageViewModel` so the migration completes before any UserDefaults read or `WKWebsiteDataStore(forIdentifier:)` lookup.
- **SandboxMigration.swift** — One-shot migration that fires on first launch after the App Sandbox entitlement was removed. Copies `~/Library/Containers/com.claudetracker.app/Data/Library/Preferences/com.claudetracker.app.plist` → `~/Library/Preferences/com.claudetracker.app.plist` (UserDefaults), and copies any per-identifier `WKWebsiteDataStore` directories from `Library/Containers/.../WebKit/WebsiteDataStore/<UUID>` → `~/Library/WebKit/com.claudetracker.app/WebsiteDataStore/<UUID>` (cookies, IndexedDB, LocalStorage). WebKit data-store directory layout is portable across paths — `WKWebsiteDataStore(forIdentifier:)` doesn't care which absolute path holds it. Gated by the `sandboxMigrationCompleted` UserDefaults flag, which is **only written when both steps succeed or verifiably have nothing to migrate** — a transient failure (unreadable plist, copy error) is retried on the next launch instead of permanently losing data. Both steps are idempotent: existing destination keys/stores are never overwritten, so a partial re-run can't clobber session state.
- **ClaudeAPIService.swift** — Networking via a hidden `WKWebView` that calls `fetch()` through `callAsyncJavaScript`. This bypasses Cloudflare bot protection which blocks plain `URLSession` requests. Also handles login flow (loads claude.ai login page, polls cookies for `sessionKey` via a MainActor task loop — `startCookiePolling`/`stopCookiePolling`). Uses `.defaultClient` content world. **Readiness robustness:** `ensureReady()` waiters are keyed by UUID, cancellation-aware (`withTaskCancellationHandler` removes a cancelled caller's continuation), and covered by a shared 30 s timeout (`armReadinessTimeout`) that fails all waiters if the page never becomes ready (e.g. a stuck Cloudflare challenge) — without this a stuck page would suspend callers forever and silently stop polling. `checkPageReady` treats a JS-evaluation *error* as page-dead and fails fast (a nil-result blank title still counts as ready), and `webViewWebContentProcessDidTerminate` resets state, fails waiters, and reloads so a killed WebKit process recovers instead of looping on errors. A `DecodingError` from `fetchUsage` logs the first 500 bytes of the payload before rethrowing so API format changes are diagnosable from the log file. `HTTPCookie.isClaudeDomain` (extension in this file) is the single cookie-domain predicate. **Per-account isolation:** `init(dataStoreIdentifier: UUID)` builds the `WKWebViewConfiguration.websiteDataStore` from `WKWebsiteDataStore(forIdentifier:)` (macOS 14+) so cookies, IndexedDB, and the `sessionKey` cookie are per-account. `tearDown()` cancels cookie polling, drops the popup, stops loading, and nils delegates so the data store can be safely passed to `WKWebsiteDataStore.remove(forIdentifier:)` during account removal. OAuth SSO (e.g. "Continue with Google") is handled via `WKUIDelegate.createWebViewWith`: returns a real `WKWebView` built from the *passed* `configuration` (so it shares the data store and `window.opener` is wired). Only `uiDelegate` is set on the popup — `navigationDelegate` is intentionally omitted to prevent popup navigations from misfiring `failAllWaiters`/`checkPageReady` on the main webview. `webViewDidClose` fires when JS calls `window.close()` on the popup. Three properties coordinate with `LoginWindowController`: `popupWebView`, `onPopupRequested`, `onPopupDismissed`.
- **UsageViewModel.swift** (+ **UsageViewModelAccounts.swift**, **UsageViewModelAlerts.swift**, **UsageViewModelMenuBar.swift**) — Central state, split across one class and three same-type extension files: the main file holds preferences, computed accessors, startup, and polling; `UsageViewModelAccounts.swift` holds the account roster lifecycle + legacy migration + chart-history persistence; `UsageViewModelAlerts.swift` holds reset detection, toast/sound dispatch, and pace history; `UsageViewModelMenuBar.swift` holds the composed menu bar image. Manages adaptive polling (async `Task`-based loop, no fixed interval), persistence (`UserDefaults`, all keys via the `PrefKey` namespace in Models.swift), backoff on errors, session state, and notification dispatch. **Multi-account:** holds `accounts: [Account]` (persisted via `AccountStore`), `activeAccountID: UUID?`, `statesByAccount: [UUID: AccountState]`, and `apiService: ClaudeAPIService?` rebuilt against the active account's data store. Top-level vars `usage`, `error`, `lastUpdated`, `accountInfo`, `usageHistory`, `isAuthenticated` are **computed accessors** over the active slice, so view-layer code reads the same names. `fetchUsage` captures `let id = activeAccountID` at task start and writes results to `statesByAccount[id]?.field` (not the active one) so a mid-fetch `switchAccount` cannot cross-contaminate state. `addAccount(label:)` creates an `Account` with a fresh `dataStoreIdentifier` and makes it active; `openLoginForNewAccount()` wraps `addAccount` + `LoginWindowController.open` so view call sites need only one line; `cancelPendingAdd(_:)` rolls back when the user closes the login window without signing in. `cancelInFlightWork()` cancels `fetchTask`/`sessionTask`/`timer` and resets `isLoading` — used by `switchAccount`, `addAccount`, and `removeAccount`. `startSession()` captures `apiService`/`activeAccountID` *at call time*, stores its task in `sessionTask` (so it's covered by `cancelInFlightWork`), and re-checks `id == activeAccountID` before `startPolling()` — an account switch mid-await can neither misattribute the result nor spawn a competing poll loop. `switchAccount(to:)` cancels in-flight work, dismisses the outgoing account's pace toasts, persists the new selection, and triggers a fresh fetch. `removeAccount(_ id:)` tears down the API service, calls `WKWebsiteDataStore.remove(forIdentifier:)`, removes the namespaced `usageHistory.<id>` key, and switches to the next account or empty state. `migrateLegacySessionIfPresent()` runs as an async post-init Task gated on `accountsMigrationVersion < 1`: copies cookies from `WKWebsiteDataStore.default()` into a freshly created per-id store, registers a single `Account`, and renames `usageHistory` → `usageHistory.<id>`. **Adaptive polling:** `scheduleNextPoll()` calls `computeAdaptiveInterval()` after every fetch and sleeps for the computed duration before the next one. Interval is the minimum across both windows of `intervalForWindow(key:window:)`, which delegates to the pure, unit-tested `pollInterval(utilization:resetsAt:projectedMinutes:now:)` in Models.swift: stale window (reset already passed) → 2 s; at 100% → 10–300 s based on time until reset; active (pace available) → 1–10 s based on projected minutes to full; fallback (no pace) → 3–10 s based on utilization level. Error backoff adds `errorBackoff(consecutiveErrors:)` (`min(n × 10, 60)` s) on top. Each poll logs the chosen interval and utilization via `AppLogger`. Generates the composed `menuBarImage` (SF Symbol + utilization text + optional pace badge baked into one `NSImage`); the icon and utilization badge color use a continuous urgency gradient via `urgencyNSColor()` (green → yellow → orange → red) based on `effectiveUrgency = max(utilizationUrgency, paceUrgency)` — the icon also elevates when pace alone is high even at low utilization. The utilization text uses `labelColor`; the pace badge (`menuBarPaceText`) uses `urgencyNSColor(paceUrgency)` independently. SF Symbol secondary palette color is `.labelColor` (not `.white`) for contrast at mid-urgency. Cache is keyed on icon + text + color + paceText + paceColor + `NSApp.effectiveAppearance` name. **The cache properties (`cachedMenuBarKey`/`cachedMenuBarImage`) are `@ObservationIgnored`** — the `menuBarImage` getter runs inside the `MenuBarExtra` label's body, and writing an observed property there schedules an immediate second render of every menu bar update. The observed redraw signal is `menuBarImageVersion`, bumped by `invalidateMenuBarImage()` (which also clears the key); appearance changes (observed via `NSApp.publisher(for: \.effectiveAppearance)`), account switches, and sign-outs all call it. Notification preferences are persisted per-key. Pace system: appends utilization readings to a 5-minute rolling history window; `pace(for:)` delegates to `computePace(history:lambda:2.0)` in Models.swift; requires ≥2 points and 15 s elapsed. Reset-guard in `recordHistory` clears history via the pure, unit-tested `shouldResetPaceHistory(last:current:)` (`drop > 20 || (utilization < 5 && last >= 5)`) — the `< 5` clause catches resets from low utilization that the `> 20` drop threshold would miss. Chart snapshots go through the pure `appendPrunedDataPoint(_:to:lastTimestamp:)` (5-min throttle, 30-day prune, 8640 cap). `showPace` controls popover pace rows; `showPaceMenuBar` controls the menu bar badge (independent); `paceRateUnit` (`PaceRateUnit`: perHour/perMinute/perSecond, persisted under `"paceRateUnit"`) selects the time unit for all rate displays — the internal rate is always computed in %/hr and converted at display time via `PaceRateUnit.format(_:prefix:short:)`. Reset detection uses parsed `Date` values (not raw strings) with a 1-hour threshold to guard against server timestamp noise. `paceToastIDs: [String: UUID]` tracks active pace-alert toasts; they are dismissed automatically (via `ToastWindowController.dismiss(id:)`) when the pace improves past the warning threshold, or when a window reset is detected in `recordHistory`. `@Published var popupScale: Double` (default `1.0`, persisted under `"popupScale"`) drives proportional scaling of all popover elements. **Update system:** extracted to `UpdateService` (see its own entry); `UsageViewModel` holds it as `var updates` and the wake observer calls `updates.checkForUpdates()`. **Stale data:** `isDataStale` returns `true` when a usage window's `resetsAtDate < now && lastUpdated < resetsAtDate` — i.e. the window reset while the app wasn't running (Mac asleep). `statusText`/`statusIcon`/`statusColor` return neutral values when stale. **Startup:** `init()` calls `loadPersistedPreferences()` (private) which reads all UserDefaults keys — including the v2 migration — then sets `isInitialized = true`. `isInitialized` guards all `didSet` sound triggers so UserDefaults loading doesn't play sounds at startup. **Construction vs. startup:** `init()` is side-effect-free (just `loadPersistedPreferences()` + `isInitialized = true`), so `UsageViewModel()` is constructible in tests; all live work — the wake observer, `loadAccountsAndStartActive()`, the appearance subscription, and `updates.start()` — moved to `start()`, called once from `ClaudeTrackerApp.init()`. Session-recovery: the first consecutive 401 retries silently; a second consecutive 401 marks the session expired and cancels the timer. `usageHistory: [UsageDataPoint]` stores chart snapshots sampled at most once per 5 minutes (throttled by `lastHistoryTimestamp`), pruned to 30 days, capped at 8640 entries, JSON-encoded in UserDefaults under `"usageHistory"`. `showChartsTab: Bool` (persisted under `"showChartsTab"`, default `true`) controls visibility of the Charts tab.
- **UpdateService.swift** — `@Observable @MainActor` class owning the in-app update flow, extracted from `UsageViewModel` (held as `var updates`; `var` not `let` so `@Bindable`'s `$viewModel.updates.autoUpdate` resolves to a reference-writable key path). `checkForUpdates()` fetches `api.github.com/repos/.../releases?per_page=10` via plain `URLSession` (non-200 responses and network errors are logged via `AppLogger` — a silent failure would be undiagnosable), parses the payload with the pure, unit-tested `parseGitHubReleases(_:currentVersion:)` (file-scope; tolerates GitHub's rate-limit error dict), exposes a newer version as `availableUpdate: UpdateInfo?`, and notifies once per version (`lastNotifiedUpdateVersion`). The next-check interval comes from the pure `adaptiveCheckInterval(from:)` (`clamp(avgGap/2, 4h, 24h)`, in Models.swift), stored in `nextCheckInterval` / `PrefKey.updateCheckInterval`; `schedulePeriodicUpdateCheck()` arms a MainActor sleep-loop task only while `autoUpdate` is on. `autoUpdate: Bool` gates `downloadAndInstall()`, which downloads the `.zip`, unzips via `Process`, **verifies the extracted bundle's `CFBundleShortVersionString` is actually newer** (`bundleShortVersion(at:)` — the asset could have changed since the check), then installs via the pure, temp-dir-tested `atomicReplaceItem(at:with:)` — a stage-and-swap (copy → move old aside → rename in → delete old, with rollback) so a failure at any step leaves either the old or the new bundle in `/Applications`, never nothing — and relaunches; `updateDownloadState` (`idle/downloading/installing/failed`) drives progress UI. `start()` loads the persisted update prefs and fires the initial +10 s check — called from `UsageViewModel.start()`, never from an initializer, so a bare `UpdateService()`/`UsageViewModel()` in a test does no I/O. Views read `viewModel.updates.<x>`; transitive `@Observable` tracking keeps them current.
- **Models.swift** — Codable structs matching the API response: `UsageResponse` with `five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet` windows, each containing `utilization` (0–100%) and `resets_at` (ISO 8601, **nullable** — the API returns `null` immediately after a reset while computing the new window). `UsageWindow.resetsAt` is `String?`; `resetsAtDate` guards on nil and then tries two formatters (with and without fractional seconds). **`UsageResponse` decodes fail-soft:** each sub-window decodes independently (`init(from:)` with `try?`), so a malformed window the UI doesn't even display (e.g. `seven_day_opus` shipping `"utilization": null`) becomes nil instead of poisoning the whole response; a full decode failure surfaces as a friendly "API format changed" error with the payload head logged. `UsageWindow.utilizationColor` uses `urgencyColor()` for a continuous green→yellow→orange→red gradient. `urgencyColor(_ urgency: Double) -> Color` is a free function (hue = `0.33 * (1 - t)`) shared by the popover and the AppKit layer (which has a matching `urgencyNSColor` in `UsageViewModel`). `paceUrgencyColor(proj:hoursToReset:) -> Color` is a free function with the shared 3-band logic for all pace UI (rate text, outlook message, chart projection line): `.secondary` when `proj >= hoursToReset`, `urgencyColor(0.7)` when `>= 0.8 ×`, else `urgencyColor(1.0)`. `AccountInfo` derives the subscription label from `memberships[0].organization.capabilities` (e.g. `"claude_max"`) and `rate_limit_tier` (e.g. `"default_claude_max_5x"`). Also `MenuBarWindow` enum for the display picker, `PaceRateUnit` enum (perHour/perMinute/perSecond) with `format(_:prefix:short:)` converting %/hr to the selected unit for all display sites, `UpdateInfo` struct for the update checker, `UsageDataPoint` (`timestamp`, `fiveHour?`, `sevenDay?`, `Identifiable` by `timestamp`) for the charts history, and `computePace(history:lambda:)` — the pace rate function using exponentially-weighted linear regression (configurable λ, default 2.0, minimum 15 s elapsed, returns %/hr and projected hours-to-full). Pure, unit-tested helpers also live here: `adaptiveCheckInterval(from:)` (update cadence), `isWindowReset(previous:next:utilization:)` (reset detection), `windowIsStale(resetsAt:lastUpdated:now:)` (stale detection), `pollInterval(...)` + `pollIntervalForProjectedMinutes(_:)` + `errorBackoff(consecutiveErrors:)` (adaptive polling tiers), `shouldResetPaceHistory(last:current:)` (pace reset guard), `appendPrunedDataPoint(...)` (chart-history throttle/prune/cap), `prefers24HourClock(_ locale:)` (first-run seed for the Time format setting), `pinnedHourCycleLocale(use24Hour:base:)` (copy of a locale with the hour cycle pinned to the user's 12/24-hour choice — shared by `resetTimeText` and the chart axis labels), `resetTimeText(reset:now:use24Hour:includeDate:calendar:locale:)` (absolute reset time next to the countdown — hour cycle pinned via `pinnedHourCycleLocale` so the user's 12/24-hour choice beats the locale preference; abbreviated weekday prepended when the reset is not today, and `includeDate: true` — used by the 7-day windows — adds abbreviated month + day with ICU's locale date–time connector, e.g. "Thu, Jul 9 at 17:00"), and `PaceBand` (the safe/close/over classification behind `paceUrgencyColor` and the pace outlook messages — the 0.8× threshold lives only there). `PrefKey` is the namespace for **all** UserDefaults preference keys — never write a key as a string literal. All model types are `Sendable`. **Multi-account types:** `Account` (id, label, email, subscriptionLabel, orgName, dataStoreIdentifier, addedAt; `Codable + Identifiable + Hashable`) — the optional fields use `decodeIfPresent` so older persisted accounts migrate transparently. `AccountStore` (UserDefaults helper for the `accounts` JSON array, `activeAccountID`, and per-account `usageHistory.<id>` key), and `AccountState` (per-account runtime bucket: `usage`, `error`, `lastUpdated`, `accountInfo`, `previousResetsAt`, `utilizationHistory`, `paceWarned`, `paceToastIDs`, `lastHistoryTimestamp`, `usageHistory`, `consecutiveErrors`, `sessionExpired`).
- **LoginView.swift** — `NSViewRepresentable` wrapping the API service's `WKWebView` for in-app browser login. `LoginWindowController` (now `@MainActor`) manages the login window lifecycle (singleton, reuses existing window on repeated opens). **Reuse rebinds, never recycles:** when `open` is called while the window is already visible, the previous attempt's `onCancel` runs first (rolling back its abandoned placeholder account), then the window's content view is replaced with a fresh `LoginView` bound to the *new* `apiService`/`onSessionFound` — keeping the old content view would capture the session into the wrong account's data store. `open(apiService:onSessionFound:onCancel:)` accepts an `onCancel` closure that fires via the login window's `willCloseNotification` if the user closes the window without ever capturing a session — used by `addAccount` to roll back the placeholder `Account` row and call `WKWebsiteDataStore.remove(forIdentifier:)`. Also manages the OAuth popup window: `showPopup(webView:)` creates a child `NSWindow` using the `WKWebView` returned by `createWebViewWith`, wired via `onPopupRequested`/`onPopupDismissed` closures on `ClaudeAPIService`. `closePopup()` removes the `NSWindow.willCloseNotification` observer before closing to avoid re-entrancy. Both the login window and the popup window require `isReleasedWhenClosed = false` — omitting this causes a double-free crash (ObjC autorelease + Swift ARC release) during Core Animation teardown.
- **AppLogger.swift** — Rolling file logger singleton. Writes to `os.log` (visible in Console.app) and to `~/Library/Logs/ClaudeTracker/claudetracker.log` (512 KB max, one rotation to `claudetracker.1.log`). `info()` and `error()` methods; `tail(maxBytes:)` for recent log content; `logFileURL` for the "Open Logs" button in Settings. All API fetch errors and update installer errors are routed through `AppLogger.shared.error(...)`.
- **ToastWindowController.swift** — Floating `NSPanel`-based toast notification. Uses `[.borderless, .nonactivatingPanel]` styleMask, `.floating` level, `isOpaque = false`, `backgroundColor = .clear` so the SwiftUI material fills the visual area. Positioned at top-right corner (exact icon position is not accessible from `MenuBarExtra`). `show()` is `@discardableResult` and returns a `UUID`; callers that need caller-driven dismissal store it and call `dismiss(id:)`. Reset-notification call sites discard the UUID; pace-alert call sites store it in `paceToastIDs`.
- **MenuBarView.swift** (+ **MenuBarChartsView.swift**, **UsageWindowView.swift**, **PopoverResizer.swift**, **SharedViews.swift**) — Popover UI with two tabs: **Usage** (progress bars, reset countdowns, pace, extra usage) and **Charts** (historical area+line charts). The former 1000-line file is split: `MenuBarView.swift` keeps the shell (header, account picker, update banner, usage rows, footer); `MenuBarChartsView.swift` is the Charts tab as its own struct owning the chart state (`chartTimeRange`, shared hover `selectedTime`) plus `MiniChartView`, `ChartHoverModifier`, `ChartTimeRange`, and the forecast charts — extracting it means Usage-tab poll updates don't re-execute chart builders. **The visible-history slice is computed inline in `body`, never cached in `@State` filled by `onChange`:** the struct is recreated on every tab switch, and a state cache starts empty — the first committed frame would render the short "No data" layout and the tall charts one beat later, double-resizing the popover (visible shake); `UsageWindowView.swift` is the per-window row (its `paceOutlook` switches on `PaceBand`; the reset line appends the absolute reset time via `resetTimeText`, driven by `viewModel.use24HourTime` passed as `use24Hour` from both call sites, plus `includeResetDate` — `true` for 7-day windows (`windowKey == .sevenDay` and the Sonnet row) so they show month + day, `false` for the 5-hour window; the whole reset line is hidden when `isStale` — a passed reset would make the self-updating relative style count upward, rendering "Resets in" directionally wrong); `PopoverResizer.swift` is the position-pinning AppKit bridge; `SharedViews.swift` holds `SubscriptionBadge` (used in 3 places) and `ScaledSegmentedPicker` (backs both the tab selector and the time-range picker). **Hover writes are quantized to the minute and deduplicated** in `ChartHoverModifier` — raw per-pixel dates would re-evaluate the whole charts subtree on every mouse move. **Header account picker:** when `viewModel.accounts.count >= 2` the title bar shows a `Menu` (chevron) listing each account + "Add account"; selecting one calls `viewModel.switchAccount(to:)`. Single-account installs see the original subscription badge with no picker. **Sonnet bar:** `usageWindows(_:)` appends a third `UsageWindowView` for `usage.sevenDaySonnet` when the API returns it AND `viewModel.showSonnetWindow` is true. Pace is computed identically to the other windows: stale or ≥100% suppresses it; otherwise `viewModel.pace(for: "seven_day_sonnet")` is passed. `recordHistory` appends `seven_day_sonnet` utilization into its own history bucket; `checkPaceNotifications` includes it in the candidates list gated on `notify7Day && showSonnetWindow`. Tab selection is stored in `@AppStorage("selectedTab")` and persists across popover opens. The tab selector is a custom segmented control (`tabButton`) shown only when authenticated and `showChartsTab == true`; toggling `showChartsTab` off resets `selectedTab` to 0 via `onChange`. Charts use `import Charts` (system framework, no xcodeproj change needed); `miniChart` renders an `AreaMark` + `LineMark` with `.monotone` interpolation. Both `miniChart` and `forecastChartBody` share a `ChartHoverModifier` (fileprivate `ViewModifier`) applied via `.chartHoverSelection(_:)` — it wires the `chartOverlay` + `GeometryReader` hover-to-date mapping onto any `Chart` view. Chart hour:minute axis/hover labels come from `chartAxisFormat(forSpan:use24Hour:)`, which pins the hour cycle via `pinnedHourCycleLocale` so chart times honor the Time format setting like the reset line does. Chart color for both utilization and pace uses `urgencyColor(min(lastValue/100, 1))` — green at low values, red at high — so pace charts reflect urgency as well. Stats row shows "now X  pk Y  avg Z"; "now" is the latest sampled value. Charts are hover-interactive: `@State private var selectedTime: Date?` is shared across all four mini-charts; hovering over any chart updates `selectedTime`, triggers a dashed `RuleMark` on all charts at that time, and replaces the "now" label with "@ X" (value at the hovered point). Hover implemented via `.chartOverlay { proxy in GeometryReader { ... onContinuousHover } }` using `proxy.plotFrame` for coordinate mapping. All spacing, padding, and font sizes are multiplied by `s = CGFloat(viewModel.popupScale)`. `baseWidth` is `312 * s`. `ChartTimeRange` enum (`1h`/`5h`/`24h`/`7d`/`30d`) controls how much history is displayed; selection persisted via `@AppStorage("chartTimeRange")`. **Outlook chart:** each `windowCharts` section also renders a `projectionChart` (label "Outlook") when the current `UsageWindow` has a valid `resetsAtDate`. It spans the entire current window (windowStart to max(resetDate, projectedFullDate)) and shows three series: a gray dashed diagonal for the expected linear rate (0% at start → 100% at reset), the actual historical data as a gray area+line, and a dashed colored line extrapolated from the last sample at the current pace rate. The accent color comes from the shared `paceUrgencyColor(proj:hoursToReset:)` helper in `Models.swift` — also used by `paceLine` (rate text) and `paceOutlook` (message) so all three pace elements stay color-aligned. `projectionChart` always reads from `viewModel.usageHistory` (not the time-range-filtered `visible` slice) so the full window period is always shown regardless of the selected `ChartTimeRange`. **Stale color fix:** `UsageWindowView` uses `.secondary` color (not `window.utilizationColor`) for the utilization percentage text and progress bar tint when `isStale == true`, preventing red/orange display after a reset while waiting for fresh data. **Update banner:** `updateBanner(_:)` shown immediately below the header whenever `viewModel.availableUpdate` is non-nil; shows version, Install/Download action, and live progress states (downloading/installing via `updateDownloadState`). **Stale data banner:** shown in `usageWindows()` instead of the error row when `viewModel.isDataStale` is true.
- **SettingsView.swift** — **Accounts list** at the top: one row per account showing label (plain `Text`), subscription badge, email, plus row buttons Switch (when not active), pencil (rename via alert), and trash (remove with confirmation alert). The "Add account" button lives in the section header, right-aligned next to the "Account" title. Removed the old single-account "Sign out" button — sign-out is now folded into "Remove account". ## Key Constraints

**Toggle styling in Form — NEVER use `.tint` or `.toggleStyle(.switch)` on `Toggle` inside a `Form`:** SwiftUI `Form` with `.formStyle(.grouped)` creates environment-isolation boundaries that prevent `.tint(.green)` from reaching the underlying `NSSwitch` renderer. Any approach relying on environment tint (`.tint(.green)`, per-toggle `.tint`, even `AnyView` wrappers) will regress to system gray whenever macOS redraws the cell. The only permanent fix is `GreenSwitchStyle` — a custom `ToggleStyle` that renders an entirely SwiftUI capsule+circle, bypassing `NSSwitch` and its environment completely. The drawn control is wrapped in a plain `Button` (keyboard focus + Space activation) with an `accessibilityRepresentation` exposing real toggle semantics to VoiceOver — keep both when touching it. Every `Toggle` in `SettingsView` must use `.toggleStyle(GreenSwitchStyle())`. Do not add `.tint` or `.toggleStyle(.switch)` anywhere in the settings form.

**Menu bar label rendering:** macOS `MenuBarExtra` labels cannot reliably show SF Symbols alongside `Text`. The only approaches that work:
- Plain `Text("string")` with no images
- Single `Image(nsImage:)` with icon + text composited into one `NSImage` (current approach)

The image does **not** use `isTemplate = true` — the icon color is applied via `NSImage.SymbolConfiguration(paletteColors:)` and the text always uses `NSColor.labelColor` (adapts to dark/light mode). Appearance changes are observed via `NSApp.publisher(for: \.effectiveAppearance)` to invalidate the cache and trigger a redraw.

Do NOT attempt `HStack { Image; Text }`, `Label(text, systemImage:)`, `Text("\(Image(...)) text")`, or the `MenuBarExtra(title, systemImage:)` init — all show the icon but hide the text.

**Login window memory management:** The `NSWindow` created by `LoginWindowController` must have `isReleasedWhenClosed = false`. The default (`true`) causes the window to be added to the ObjC autorelease pool on `close()`, while Swift ARC also holds a strong reference via `self.window`. Setting `self.window = nil` after `close()` results in a double-release that crashes during the next Core Animation transaction flush.

**Notifications:** `UNUserNotificationCenterDelegate` must be a separate `NSObject` subclass — assigning a `@MainActor` class as delegate causes Swift concurrency compiler errors. Sound is handled by `NSSound` independently of `UNUserNotificationCenter` to prevent double-play when both channels are enabled.

**Reset detection:** `previousResetsAt` stores parsed `Date` values, not raw `resets_at` strings. The API returns timestamps in varying ISO 8601 formats (with/without fractional seconds) and may use rolling expiry times — string equality would fire spurious reset notifications on every poll. A reset is only declared when the new expiry date is **more than 1 hour later** than the stored one (`newDate.timeIntervalSince(oldDate) > 3600`), which real resets (5-hour: ~5 h jump, 7-day: ~7 d jump) always satisfy.

**UserDefaults migration:** `notificationDefaultsVersion` tracks applied migrations. Version 2 reset defaults to toast-only. Increment this key and add a migration block in `UsageViewModel.init()` whenever defaults need to change for existing installs. Separately, `accountsMigrationVersion` (gated to `< 1`) drives the one-shot legacy-session import in `migrateLegacySessionIfPresent()` — copies cookies from `WKWebsiteDataStore.default()` into a per-id store and registers the first `Account`. Bump this key with a fresh migration if the account schema changes.

**Popover position pinning:** `PopoverResizer` (in `PopoverResizer.swift`) captures the panel's `(origin.x, maxY)` on first appearance and re-pins to that on every height change. It installs **two** per-window observers that snap the panel back synchronously inside the notification: `didMoveNotification` (AppKit drags the popover when the status item re-anchors — every utilization width change, pace badge appearance, account switch) and `didResizeNotification` (SwiftUI auto-sizes the panel for new content, e.g. switching the Usage/Charts tab — NSWindow frames are bottom-left anchored, so a size-only change moves the *top* edge visibly and posts no move notification; without this observer the top correction waits for the next deferred `updateNSView` pass and renders a visible jump-then-snap "shake"). A reentrancy flag (`isSnapping`) prevents the observers from recursing on their own `setFrame` calls. Removing this pinning logic causes the popover to drift sideways across data updates and bounce vertically on tab switches.

**`NSApp` is nil at `@State` init time on macOS 26:** any code in `UsageViewModel.init()` that touches `NSApp` (e.g., `NSApp.publisher(for: \.effectiveAppearance)`) crashes with "Unexpectedly found nil while implicitly unwrapping an Optional value" because the view model is allocated as a `@State` initializer inside `ClaudeTrackerApp.init()`, before `NSApplication.shared` is set up. Defer such calls onto the next main-actor turn (`Task { @MainActor in ... }`) so they run after the app is fully alive.

**Menu bar image caches must stay `@ObservationIgnored`:** the `menuBarImage` getter executes inside the `MenuBarExtra` label's body. If `cachedMenuBarKey`/`cachedMenuBarImage` were observed, the getter's cache writes would schedule an immediate second render of every menu bar update. Redraws are driven by the observed `menuBarImageVersion` counter via `invalidateMenuBarImage()` — never write the caches from view code and never remove the `_ = menuBarImageVersion` read from the getter.

**Strict concurrency is `complete` project-wide** (`project.yml` `settings.base`). The build is warning-free under it; keep it that way. Patterns used at the AppKit boundaries: MainActor task loops instead of `Timer`/Combine timers, `MainActor.assumeIsolated` inside `queue: .main` notification blocks and AppKit completion handlers, `Task<Void, Never> { @MainActor in ... }` for the deferred-one-turn representable setup (the explicit generic avoids an `init(name:priority:operation:)` overload ambiguity on Xcode 26.5), and `nonisolated(unsafe)` only for the documented-thread-safe `ISO8601DateFormatter` statics.

**Per-account state mutation must reassign the array:** `renameAccount(_:to:)` does `var copy = accounts; copy[idx].label = trimmed; accounts = copy` — a direct subscript-mutate (`accounts[idx].label = trimmed`) sometimes fails to fire `@Observable` redraws for views that read `viewModel.accounts.first(where:).label` (e.g., the `Menu` label in the popover header). Reassigning the array unconditionally guarantees the redraw.

**Sandboxing:** The app is **not sandboxed** — `ClaudeTracker.entitlements` is empty. The in-place auto-updater (`UpdateService.downloadAndInstall()`) runs `/usr/bin/unzip` via `Process` and replaces the bundle in `/Applications`, neither of which a sandboxed app can do, so the app ships without the `com.apple.security.app-sandbox` entitlement. Distribution is via GitHub Releases (Hardened Runtime + notarization), not the App Store, so this is policy-compliant. The legacy sandbox container path (`~/Library/Containers/com.claudetracker.app/Data/...`) is preserved untouched after `SandboxMigration` runs, so reverts are non-destructive.

**Hardened Runtime:** The Release target build config has `ENABLE_HARDENED_RUNTIME = YES`. This is required for Apple notarization. Do not remove it from the app target's `configs.Release` in `project.yml`.

**SourceKit false positives:** Persistent "Cannot find type X in scope" errors appear in SourceKit for all cross-file references. These are IDE-level issues and do not reflect real build errors. All builds succeed normally.

**Localization:** The app is localized for English (default) and Spanish via `ClaudeTracker/Localizable.xcstrings` (Xcode 15+ String Catalog format). English is the development language; Spanish translations are in the same file under `"es"` locale keys. All user-visible strings use `Text("literal")` (auto-`LocalizedStringKey`), `String(localized:)`, or `String(format: String(localized:), ...)` for format strings. `allWindows` returns `[(MenuBarWindow, UsageWindow)]` — use `.rawValue` for API key lookups and `.label` for display; do not compare localized label strings. To test Spanish: `defaults write com.claudetracker.app AppleLanguages '(es)' && make run`; to reset: `defaults delete com.claudetracker.app AppleLanguages`.

## Testing

`ClaudeTrackerTests/` has three files: `ClaudeTrackerTests.swift` (original model/helper tests), `PureLogicTests.swift` (polling tiers, backoff, pace reset guard, chart-history pruning, `PaceBand`, `PaceRateUnit.format`, urgency colors, plus `APIFixtureTests` — JSON fixture decoding for `UsageResponse`/`AccountInfo`/legacy `Account` rosters and `parseGitHubReleases` — and `AtomicInstallTests`, which exercises `atomicReplaceItem`/`bundleShortVersion` against real temp directories). When changing API models, keep the fixture tests in sync — they are the only guard against `CodingKeys` typos, since the other tests use memberwise inits. New persisted fields on `UsageDataPoint`/`Account` must be optional (decode-or-wipe persistence would destroy users' history otherwise). New behavioral logic should follow the established pattern: pure function in Models.swift + tests, thin delegation from the view model.

## API Notes

The app uses **unofficial, undocumented** claude.ai endpoints via WKWebView `fetch()`:
- `GET /api/account` — account profile (name, email, memberships with capabilities and rate_limit_tier)
- `GET /api/organizations` — org list with UUIDs
- `GET /api/organizations/{id}/usage` — usage windows (five_hour, seven_day, seven_day_opus, seven_day_sonnet, extra_usage)

Auth is handled by cookies in the WKWebView's `.default()` data store (shared between login and API webviews). Direct `URLSession` requests to claude.ai are blocked by Cloudflare. The subscription tier has no dedicated field — it is inferred from `capabilities` + `rate_limit_tier` in the memberships array.
